Build with QHooks

Quote one exact pool. Build an unsigned swap.

Use the reusable helper in a browser or Node 18+, or run the Node CLI. Both use the public SDK without dependencies. This example supports quote-token buys on listed QHooks pools on Base, Robinhood Chain, Ethereum, Arbitrum and BNB Chain.

Choose the identity and limits.

Read GET https://qhooks.com/api/v1/pools?chain=8453 and choose the exact poolId. Supply the trader’s public EVM address, the quote currency’s address and decimals from that pool, and a positive raw integer amount. No pool is selected automatically.

const input = {
  chainId: '8453',
  poolId: 'YOUR_EXACT_BYTES32_POOL_ID',
  trader: 'YOUR_PUBLIC_EVM_TRADER_ADDRESS',
  amountIn: '20000000', // 20 units only when quoteDecimals is 6
  quoteCurrency: 'THE_POOL_QUOTE_CURRENCY_ADDRESS',
  quoteDecimals: 6,
  route: 'rewards', // choose 'rewards' or 'direct'
  slippageBps: 100, // 100 = 1%; example accepts 0–500
  deadline: YOUR_EXPLICIT_UNIX_SECOND_DEADLINE
  // referrer: 'OPTIONAL_PUBLIC_EVM_REFERRER_ADDRESS' // rewards only
};

The deadline must be in the future and no more than 30 minutes away. The helper rechecks it after reads and before returning calldata. Slippage and deadline are encoded into the actual SDK transaction. These example limits are integration choices, not an assertion that every trade within them will succeed.

Pick the route.

  • Rewards: the 1% QHooks router fee is taken from gross input. The V4Quoter simulates the remaining input as the trader. The build uses prepareFeeRouterSwap with that gross input, the minimum quoted output, explicit deadline and optional referral address. The helper refuses an undeployed or unknown rewards router; it does not return or send a setup transaction. Cashback and referral accounting follow the router’s rules.
  • Direct: the full input is quoted and universalRouterSwap builds the swap. There is no QHooks terminal fee or terminal cashback/referral credit. The pool’s LP, protocol and configured hook charges still apply on both routes.

Run it.

In a browser, import the helper from QHooks and call it with the explicit input:

import { quoteAndBuild } from 'https://qhooks.com/examples/partner-quote.mjs';
const review = await quoteAndBuild(input);
console.log(review); // unsigned transaction + quote, limits and allowance requirements

For Node, keep public/examples/partner-quote-cli.mjs, public/examples/partner-quote.mjs and public/sdk/qhooks.mjs in their relative directory structure. Save your input as JSON, then explicitly enable public API reads:

node public/examples/partner-quote-cli.mjs --input input.json --live

The CLI also accepts --fixture fixture.json instead of --live. A fixture contains now (Unix seconds) and responses: exact path, JSON body and optional HTTP status entries. Fixture output is marked offline and is not a live quote.

Review before any wallet action.

The output includes chain, pool, input and output currencies, gross and quoted input, router fee, quoted output, minimum output, deadline, directory rule notes, allowance requirements and { chainId, from, to, data, value }. Raw amounts remain decimal strings. ERC-20 rewards input needs an allowance to QFeeRouter; direct ERC-20 input uses Permit2 and a separate Permit2 allowance with its own expiration. Native input uses transaction value.

This example reads the public pool, chain and quote APIs. The quote request sends the displayed public trader address, pool and amount to QHooks. It does not read balances or existing allowances, connect a wallet, approve, sign, deploy or submit. A successful quote is a simulation of that request; pool rules, wallet state, gas and prices can change. Requote immediately before signing and verify the selected wallet, chain, allowances and full transaction in your own integration.
