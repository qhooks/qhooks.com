02 / RECOVER

When something gets stuck

The client asks for an API key
Select No authentication / No sign in. Use the remote HTTPS endpoint, not an invented local command or token.
Tools do not appear
Check that the URL ends in /mcp, refresh the connector's tools, and restart or reload the client if needed. An organization admin may need to allow custom connectors. Do not buy a plan just to troubleshoot this page.
HTTP 429
Wait for the returned Retry-After when present. Avoid retry loops and parallel duplicate requests.
“Refreshing” or missing data
The stored record or upstream data is unavailable. Wait and try again later. Missing data is not zero or a clean safety result.
The tool is not in the catalog
Read tools/list again. Some tools and chains are held or unavailable. Do not invent a replacement endpoint or report a preparation as completed.
A quote or prepared plan expired
Re-read state and prepare again after changing the wallet, network, amount, approvals or terms. Review the returned fees and exact calls before the intended wallet signs.
Can I paste a key here?
No. Keep signing in the wallet you control. Never send a key, seed phrase, password or wallet backup to QHooks, feedback or support.

03 / KNOW THE BOUNDARIES

Reads, plans and public data

Cached/D1 tool reads have no hourly or daily quota, with abuse protection of 60 requests per minute per IP. Actual upstream fills and fresh state reads have a separate 20-per-minute IP guard; public-only cold portfolio fills allow 5 per minute. Cache hits skip the upstream guard. Rate-limit responses include Retry-After. Feedback, signed submissions and paid-attempt limits stay unchanged. Existing market routes can apply additional limits. The live tool response and API documentation are authoritative.

A prepared transaction is not a signed or completed trade. Launches and Solana use the documented site flows; perpetual orders use their venue's signing flow. Stored QProof records are evidence, not a guarantee.

QHooks records aggregate API counts. Optional feedback stores the text you explicitly choose to send. Wallet-verified profiles, board posts and competition entry require separate signatures. Read the privacy policy and terms.
