Creator Revenue integration

Turn swap fees into creator revenue with a Uniswap v4 pool, QCreatorFeeHook and a post-quantum fee vault. Withdrawals require your wallet and post-quantum key.

Integration notes

Deploys from the Lab to Base, Robinhood Chain, Ethereum, Arbitrum One and BNB Chain; proven end to end on Base and Robinhood Chain mainnet forks.

Deploy from the Lab

Open the Lab, configure Creator Revenue, then use Deploy to a public chain. The build service compiles your hook for the chosen chain, bound to that chain’s Uniswap v4 PoolManager. Your browser re-checks the build hash.

Create a post-quantum key in the Lab. It is backed up to an encrypted file and the saved file is verified before use. Its public half is written into the fee vault when the vault is created.

The review lists every transaction with its network fee: the shared signature verifier (skipped when it already exists), the fee vault, the hook at a CREATE2 address mined for its permission bits, and the pool initialisation. You approve each one in your own wallet; there is no QHooks fee. You can stop between transactions and continue later from the same browser.

Afterwards the Lab compares each contract’s on-chain code with the build byte for byte and gives you a share page. The share page re-checks the deployment and holds the two-key withdrawal.

For a token launch with supported rules, use Create. It shows the selected chain, liquidity, rules and costs before you approve the launch. The Expert Studio exposes the full configuration.

Wire the pool

The hook binds to one PoolManager, currency pair, LP fee and tick spacing. Creator fees range from 1–1,000 basis points (0.01–10%) of the executed unspecified-currency amount. Its deployed address must encode the AFTER_SWAP and AFTER_SWAP_RETURNS_DELTA permissions.

The fee recipient is ClaimQVaultSlh. The hook mints ERC-6909 PoolManager claims to that vault as swaps occur; it does not send ordinary token deposits to it. The vault pins the PoolManager, two ordered ERC-20 currencies, its wallet owner and a 32-byte SLH-DSA-SHA2-128s public key. Its key setup costs about 2M gas, so it fits every supported chain.

Authorize a withdrawal

Both keys sign the same two-key action, the one token launches use. It covers chain, vault, account, epoch, nonce, validity window and the operation keccak256(abi.encode("QHOOKS/SLHVAULT/WITHDRAW/1", currency, amount, recipient)). The wallet signs it as EIP-712 typed data and the post-quantum key signs its canonical bytes. Anyone may submit the proof.

struct Proof {
  uint256 nonce;      // nextNonce()
  uint64 validAfter;
  uint64 validUntil;
  bytes wallet;       // 65-byte ECDSA signature
  bytes pq;           // 7,856-byte SLH-DSA-SHA2-128s signature
}
function withdrawClaim(
  address currency,
  uint256 amount,
  address recipient,
  Proof calldata proof
) external;

Both keys together can replace either key (rotateKeys). If one key is lost, the other alone starts a recovery that completes after 90 days unless the remaining key cancels it. Every change moves the authorization epoch, so old signatures stop working.

Build services and payments

The Lab generates source projects and compiles contracts through the QHooks build service. Builds are free; you pay only the network fees for your own transactions.

Never send wallet secrets or post-quantum signing keys to a build or billing endpoint. Keys stay on your device.

Compatibility notes

This bundle protects fee-claim withdrawals, not every token transfer or the underlying chain. It supports an EOA wallet owner, optionally upgraded with an EIP-7702 delegation, and two fixed ERC-20 claim currencies. Native ETH, direct ERC-20 deposits, fee-on-transfer and rebasing assets are unsupported, and direct deposits can be stranded.

Contract source stays private, so explorers show unverified code; the share page checks the deployed code against the QHooks build instead. Contracts are not independently audited. The ML-DSA ClaimQVault build (about 39.6M gas key setup, Base and BNB Chain only) remains a local download.
