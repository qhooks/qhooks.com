My QHooks
Developers

Build on QHooks.

Read every listed launch, pool, quote, trade and holder from a free public API. Use the SDK to quote through a launch’s hook and build swap transactions your users sign in their own wallets. No key, no account, no payment.

Quick start

Base URL https://qhooks.com/api/v1. Public reads use GET, return JSON with "version": 1, and allow any origin (CORS). Discover also provides the read-only JSON-RPC and alert-link POST routes below.

curl https://qhooks.com/api/v1/pools?chain=8453
import { createClient, withSlippage } from 'https://qhooks.com/sdk/qhooks.mjs';

const q = createClient({ rpc: { '8453': 'https://mainnet.base.org' } });
const [pool] = await q.pools({ chain: '8453' });
const buy = pool.key.currency0 === pool.quote.address;          // quote token → launch token
const { amountOut } = await q.quote({ pool, zeroForOne: buy, amountIn: 20_000000n, trader: me });
const tx = q.universalRouterSwap({ pool, zeroForOne: buy, amountIn: 20_000000n, minOut: withSlippage(amountOut, 100) });
// send tx ({ to, data, value }) from the user's wallet after the Permit2 approvals

Discover API

The hook board, inspector, projects, Hook Tape and compare use these routes. Paths below are relative to /api/v1 unless shown otherwise. Every body has version: 1; errors use {version:1,error,docs}. GET JSON reads are CORS-open.

RouteParameters and response
GET /hookschain, q, permission, project, qhooks=1, family, new=1, sort=swaps|pools|name, limit, offset. Default limit 50, maximum 200. Returns kind, snapshotAt, sources, coverage, total, offset, limit, chains, hooks, newSince. Search matches name, address prefix and project name. Each row has id, chainId, chainName, address, name, pools, swaps, flags, permissions, project, verified, family, qhooks, profile, capabilities. IDs are chainId_lowercaseAddress; profile links use discover-hook.html#chainId:address. First-seen rows add source:"tape", firstSeen:{chainId,block,at,poolId}; seen snapshot rows can add tape:{pools,swaps24h}.
GET /hooks/{chainId}/{address}Preserves chainId, hook, deployed, flags, permissions, qhooks, kind, docs, pools. Adds evidence, board, project, verified, family, tape, trade, capabilities, buildLike, measured, planned and, for QHooks launches, trust, launch. The evidence object carries status, reason, chainId, block, observedAt, latencyMs, codeBytes, fingerprint, deployed, owner:{status,address}, permissions:{flags,names}. Owner status is ok|none|reverted|unavailable. A failed read is status:"unavailable" with a reason; null is unavailable, never zero.
GET /hooks/compare?ids=…Two to four comma-separated hook IDs. Returns hooks with the same profile/evidence fields, shared:{family,permissions,capabilities} and differs field names. Each hook keeps its own chain, block and observation time. This is not a performance ranking.
GET /hooks/families/{fingerprint}Exact runtime family: fingerprint, codeBytes, deploymentCount, chainIds, name, deployments. The profile family is matched to the live fingerprint and contains at most twelve sample IDs. Null means no shared family was returned, including an unavailable live read.
GET /hooks/projects?category=Registry: kind, generatedAt, projects. Entries contain id, name, summary, category, website, sources:[{label,url}], provenance, qhooks, deployments:[{chainId,address,role,source}], tags. QHooks entries cover launch blocks, Lab templates and marketplace modules.
GET /hooks/projects/{id}Project fields plus live observations:[{chainId,address,status,block,codeBytes,fingerprint,owner}], bounded to eight deployments per request. No returned observation does not mean a contract is absent.
GET /hooks/tape/status?chain=Coverage per chain: official manager and deployment block, finalized head, live and historical cursors, lag or gaps, pool and swap counts, last success/failure and source used (hypersync|sqd|rpc). Coverage fields include historicalFrom, historicalThrough, liveFrom, liveThrough, finalizedBlock; swap coverage has an independent live cursor and lag. The status timestamp dates the response, not every stored row.
GET /hooks/tape/pools?chain=&hook=&limit=&cursor=generatedAt, pools, nextCursor. Finalized initialization rows: chainId, managerAddress, poolId, hookAddress, currencies, poolFee, tickSpacing, sqrtPriceX96, initialTick, blockNumber, blockHash, transactionHash, logIndex, observedAt, evidence. Evidence includes the finalized boundary, derivation version and retained raw log.
GET /hooks/tape/swaps?chain=&hook=&pool=&limit=&cursor=generatedAt, swaps, nextCursor. Rows carry chainId, poolId, hookAddress, currencies, sender, poolDeltas:{amount0,amount1,unit}, sqrtPriceX96, liquidity, tick, poolManagerFee, blockNumber, blockHash, transactionHash, logIndex, observedAt, evidence. Amounts are signed raw token base units. Apply decimals only with known token metadata. Optional bounded receipt/trace observations are distinct from fee attribution.
GET /hooks/tape/activity?chain=&blocks=1800&hook=generatedAt, window, summary, hooks, pools. Window gives requestedBlocks, fromBlock, toBlock, coverageStart, complete, liveThrough, finalizedBlock, lagBlocks. Hook rows include chainId, hookAddress, swaps, pools; pool rows include poolId, currencies. Fee summaries are PoolManager LP-fee fields. About 1,800 / 10,800 / 43,200 Base blocks represent 1h / 6h / 24h; other chain times differ. Every Tape route accepts chain (default all); every row identifies its chain. v1 covers Base (8453) and Robinhood Chain (4663), finalized only. Use nextCursor unchanged (block:logIndex) for older pools/swaps.
POST /rpcJSON-RPC 2.0 at /api/v1/rpc: qhooks_chains, qhooks_decodePermissions, qhooks_chainStatus, qhooks_getHook. The last returns the evidence object. No batches; body limit 32 KiB. Live inspection covers Base, Robinhood Chain, Ethereum, Arbitrum One and BNB Chain; other board chains have snapshot records only.
POST /api/alerts/hook-linkAbsolute path outside /api/v1. JSON {chainId,hook} returns {url}, a Telegram start link. On 503 {error:"alerts_off"}, alerts are off for now. Following occurs when the user opens the bot link. It can report new pools, each 25 newly finalized Base swaps, LP-fee moves of at least 10 bps, and runtime changes. This does not authorize trades.

Sources, limits and interpretation

Board pool/swap counts are indexed by v4.xyz at snapshotAt, with coverage.exhaustive:false; they are not exhaustive totals. The board merges hooks first seen in finalized Tape initialization logs. Live bytecode, runtime size/fingerprint, permissions and owner probes are read by QHooks at the evidence block and observedAt. The first-party Tape decodes official PoolManager logs, with bounded historical backfill and retained coverage shown in status. Scanner failures preserve the last good cursor and evidence. Poll gently; the Tape page refreshes once per 30 seconds while visible.

capabilities:[{id,title,detail,flags}] describes only what permission bits allow: “can”, never a claim about what code does. buildLike:[{kind,id,title,url,why}] returns at most three capability matches to Lab templates, blocks or modules. trust:{verifiedCreator,repoproof} labels QHooks launch records; it does not guarantee behavior. launch:{chainId,controller,url} and trade:[{chainId,token,url}] hand off to the QHooks terminal with #m=chainId:controller or #t=chainId:token; trade tokens are bounded to six.

Measured / Planned: each profile names current measurements in measured and future work in planned. Fee attribution is not measured. A PoolManager swap fee is the LP-fee field; transfers, deltas and call frames do not establish a hook’s earnings. Failed or absent values stay unavailable with reasons.

JavaScript SDK

One ES module, no dependencies and no build step: https://qhooks.com/sdk/qhooks.mjs. It runs in browsers, Node 18+, Deno, Bun and Workers. It never holds keys or sends transactions; it returns { to, data, value } for the user’s wallet.

FunctionWhat it does
createClient({ api, rpc })A client. rpc maps chain IDs to RPC URLs; quotes then run on your own node.
chains() markets() market() trades() holders() candles() pools() hook() wallet() modules()The endpoints above.
quote({ pool, zeroForOne, amountIn, trader })Exact-input quote through the hook, as the real trader.
universalRouterSwap({ pool, zeroForOne, amountIn, minOut })A direct v4 swap through Uniswap’s Universal Router, with no QHooks router fee. ERC-20 input needs approve(token, PERMIT2) and permit2Approve(token, router) first.
prepareFeeRouterSwap({ pool, zeroForOne, amountIn, minOut, feeOnInput, referrer })A swap through QFeeRouter, the router the QHooks terminal uses (1% fee, trader cashback, referral credit). Refuses while the router is not deployed on that chain; feeRouterStatus(chainId).setup is the one-time transaction that creates it.
withSlippage(amount, bps), approve(), permit2Approve(), encode()Helpers.

Routers and aggregators

QHooks launches trade on ordinary Uniswap v4 pools. Any v4 router can reach them with the pool’s PoolKey from /pools. Before routing, know these behaviours.

The launch hook

Kind qhooks-launch-blocks, permission flags 10956: beforeInitialize, beforeAddLiquidity, beforeRemoveLiquidity, beforeSwap, afterSwap, beforeSwapReturnDelta, afterSwapReturnDelta. Liquidity belongs to the launch; outside liquidity is not accepted. The hook is not upgradeable.

  • Charges come through return deltas. A launch’s taxes and other charges, plus a protocol fee (one fifth of the creator’s LP fee), are taken inside the swap. Off-chain constant-product math is not enough: quote with the V4Quoter or a full simulation. The /quote endpoint and the SDK do this.
  • Launch windows. In a launch’s first minutes, its rules can refuse a swap: a per-block buy cap, a per-wallet cooldown and wallet cap, a holder gate, an opening bell or an opening auction. router.routable is false until router.routableFrom, and the notes name each rule and when it ends.
  • Per-wallet rules use tx.origin. When an EOA sends the swap, the rules apply to that wallet even through a router. Through relayers, solvers or ERC-4337 bundlers, they apply to the relayer. Simulate with from set to the trader. Launches with an exit clock (router.quoteWithTrader) charge sells by how recently that wallet bought.
  • Price-path charges. Sandwich, impact and storm charges depend on the price before and after the swap within the block (router.dynamicFee).
  • Hook data. Empty hook data is fine. Launches with referrals accept a 32-byte referrer address.
  • Indexers. v4’s Swap event is emitted before the hook’s afterSwap, so event-only indexers see prices and volumes without the hook charges.

The ETH second pool

Kind qhooks-pair: a token/ETH pool some launches open on USDC chains. Same rules and charges, paid in the token. Exact-input swaps only.

Lab deployments

Hooks deployed from the Lab each get a share page whose link carries a qhooks-hook-deployment manifest. It holds chain, addresses, configuration, build hash and the deployed code hashes. The page re-checks the manifest against the chain, and other tools can register it.

Limits and notes

  • Responses are cached for a few seconds at the edge. Please poll no faster than every 5 seconds per endpoint.
  • Launch market endpoints show launches listed on Markets; quotes are served only for their pools. Discover includes the broader sourced hook board.
  • There are no webhooks yet; poll /markets or use the Telegram bot for alerts.
  • Hook inspections (inspector) are read-only, and paid inspection is switched off.
  • Contracts are not independently audited. Nothing here is investment advice.
