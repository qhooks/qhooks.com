Your first trading integration.

Choose a chain and a route. Read the live directory, then copy an example that quotes the pool’s actual rules and builds a transaction for your user’s wallet.

  1. ReadFind a listed pool and its routing requirements.
  2. QuoteSimulate as the actual trader, including hook charges.
  3. BuildSet the minimum output and required approvals.
  4. Review & signThe user confirms in their own wallet.

This SDK flow supports listed QHooks pools on Base, Robinhood Chain, Ethereum, Arbitrum and BNB Chain. Pool availability and router deployment are checked per chain. For other EVM tokens and Solana, open the terminal.

Run an exact-pool quote and build.

The runnable partner example takes an exact chain and pool ID, public trader address, raw quote-token amount, quote currency and decimals, route, slippage and deadline. It validates the directory, quotes the chosen route and returns unsigned SDK calldata. It connects no wallet and sends no transaction.

Choose QHooks rewards routing or direct Uniswap routing explicitly. The rewards quote uses the input remaining after the 1% router fee; direct routing has no QHooks terminal fee or terminal rewards. Pool and hook charges still apply.

Agents and MCP

Read launches, inspect a token and prepare a launch or trade from your app or assistant. The REST base is https://qhooks.com/api/v1/agent/. The MCP endpoint is https://qhooks.com/mcp, using Streamable HTTP with JSON responses. No API key is needed.

MCP toolREST routeInputs and result
list_launchesGET launchesOptional chain and limit. Recent listed launches.
token_infoGET tokenchain, token. The launch’s market detail and pools.

prepare_launchPOST prepare-launchname, ticker, optional chain, style. A prefilled /create link, chain, style and signing notes. The default style is fair.
prepare_tradePOST prepare-tradechain, token, side, amountIn, slippageBps, trader, optional referrer. Ordered unsigned transactions, the quote and minimum output. side is buy or sell; input is raw base units.

Launch preparation opens the one-tap panel for review. The post-quantum key is made in the user’s browser and stays on by default. The user’s wallet signs on qhooks.com. Trade preparation checks the fee router on the chosen chain and includes an ERC-20 approval only when the current allowance needs it. Review each {to,data,value} before asking the user’s wallet to sign and send.

Connect an MCP client

For clients with native HTTP MCP support, add this remote server. Select HTTP or Streamable HTTP if the client asks for a transport.

{
  "mcpServers": {
    "qhooks": {
      "type": "http",
      "url": "https://qhooks.com/mcp"
    }
  }
}

MCP protocol version 2025-06-18. POST only, stateless, with a 64 KiB body limit and no batch requests or event stream. Results include text JSON and structuredContent; check isError before using a tool result.

Earn from routing

Pass your app’s address as referrer on fee-router trades to receive the referral share. Use SDK feeRouterSwap({…options, referrer}), MCP prepare_trade, REST prepare-trade, or a terminal link such as https://qhooks.com/terminal?ref=0xYourAddress. Use a full EVM address in place of the example.

Partner routing shows the current fee terms, a read-only rewards lookup and an optional signed directory listing. Registration is not needed to earn. Claim rewards from your own wallet in the terminal.

Sources, limits and interpretation

Board pool/swap counts are indexed by v4.xyz at snapshotAt, with coverage.exhaustive:false; they are not exhaustive totals. The board merges hooks first seen in finalized Tape initialization logs. Live bytecode, runtime size/fingerprint, permissions and owner probes are read by QHooks at the evidence block and observedAt. The first-party Tape decodes official PoolManager logs, with bounded historical backfill and retained coverage shown in status. Scanner failures preserve the last good cursor and evidence. Poll gently; the Tape page refreshes once per 30 seconds while visible.

capabilities:[{id,title,detail,flags}] describes only what permission bits allow: “can”, never a claim about what code does. buildLike:[{kind,id,title,url,why}] returns at most three capability matches to Lab templates, blocks or modules. trust:{verifiedCreator,repoproof} labels QHooks launch records; it does not guarantee behavior. launch:{chainId,controller,url} and trade:[{chainId,token,url}] hand off to the QHooks terminal with #m=chainId:controller or #t=chainId:token; trade tokens are bounded to six.

Measured / Planned: each profile names current measurements in measured and future work in planned. Fee attribution is not measured. A PoolManager swap fee is the LP-fee field; transfers, deltas and call frames do not establish a hook’s earnings. Failed or absent values stay unavailable with reasons.

Routers and aggregators

QHooks launches trade on ordinary Uniswap v4 pools. Any v4 router can reach them with the pool’s PoolKey from /pools. Before routing, know these behaviours.

The launch hook

Kind qhooks-launch-blocks, permission flags 10956: beforeInitialize, beforeAddLiquidity, beforeRemoveLiquidity, beforeSwap, afterSwap, beforeSwapReturnDelta, afterSwapReturnDelta. Liquidity belongs to the launch; outside liquidity is not accepted. The hook is not upgradeable.

  • Charges come through return deltas. A launch’s taxes and other charges, plus a protocol fee (one fifth of the creator’s LP fee), are taken inside the swap. Off-chain constant-product math is not enough: quote with the V4Quoter or a full simulation. The /quote endpoint and the SDK do this.
  • Launch windows. In a launch’s first minutes, its rules can refuse a swap: a per-block buy cap, a per-wallet cooldown and wallet cap, a holder gate, an opening bell or an opening auction. router.routable is false until router.routableFrom, and the notes name each rule and when it ends.
  • Per-wallet rules use tx.origin. When an EOA sends the swap, the rules apply to that wallet even through a router. Through relayers, solvers or ERC-4337 bundlers, they apply to the relayer. Simulate with from set to the trader. Launches with an exit clock (router.quoteWithTrader) charge sells by how recently that wallet bought.
  • Price-path charges. Sandwich, impact and storm charges depend on the price before and after the swap within the block (router.dynamicFee).
  • Hook data. Empty hook data is fine. Launches with referrals accept a 32-byte referrer address.
  • Indexers. v4’s Swap event is emitted before the hook’s afterSwap, so event-only indexers see prices and volumes without the hook charges.

The ETH second pool

Kind qhooks-pair: a token/ETH pool some launches open on USDC chains. Same rules and charges, paid in the token. Exact-input swaps only.

Prepare a hook in your own app.

Bring the Lab’s captured hook and revenue-module templates into a launchpad, wallet or creator tool. These public endpoints support browser integrations without a wallet or API key. Preparation is available for Base, chain 8453.

EndpointReturns
GET https://qhooks.com/api/lab/catalogThe current sourceVersion, template IDs, typed fields, constructor examples, units and source snapshots.
POST https://qhooks.com/api/lab/catalog/buildA qhooks-lab-catalog-build envelope with the normalized request, captured artifactInput, unsigned artifact and additionalChecks.

Use Content-Type: application/json and a UTF-8 body up to 16 KiB. Both routes allow anonymous cross-origin requests with credentials omitted. Browser preflight supports only the route’s GET or POST method and the Content-Type header. Send no Authorization header and use credentials: 'omit'.

  • Keep the source binding. Read the current sourceVersion from the catalogue and retain it with the exact template ID and configuration. A stale or unknown source edition is refused.
  • Use the field schema. Integer values are canonical decimal strings, including signed values where allowed; use JSON booleans for boolean fields and preserve tuple/array order. Addresses, ranges, recipient counts and constructor rules are validated. Extra fields and arbitrary compiler inputs are refused.
  • Review actual pool inputs. Constructor examples are not market quotes. Choose and review the exact currencies and raw-unit starting price for your pool; amounts depend on token decimals.
import {createClient} from 'https://qhooks.com/sdk/qhooks.mjs';
const q = createClient();
const catalog = await q.lab.catalog();
const template = catalog.templates.find(t => t.id === 'policies/full-fill-only');
if (!template) throw new Error('Template unavailable in this source edition');

// Constructor example only; review your exact currencies and raw starting price.
const request = {
  kind: 'qhooks-lab-template-request', schemaVersion: 1,
  sourceVersion: catalog.sourceVersion, template: template.id,
  chainId: '8453', projectName: 'Partner full-fill hook',
  configuration: structuredClone(template.exampleConfiguration)
};
const build = await q.lab.prepareTemplate(request);
console.log(build.artifactInput, build.artifact, build.additionalChecks);

createClient({ api: 'https://your-host.example/api/v1' }) sends Lab requests to that origin’s /api/lab/catalog routes. Both Lab methods accept an optional AbortSignal. Structured API errors expose status, code and the public response body; for example invalid_request (400), body_too_large (413) or unsupported_media_type (415).

Review, then deploy.

The response prepares captured code and constructor checks. Review its source binding, code, configuration and required checks before deployment. Deployment needs a separate exact transaction plan, live dependency checks, simulation, gas and wallet review. A preparation has artifact.executionEnabled === false; it is not a deployment receipt. The Lab provides the corresponding browser review flow.

Deployment records

Hooks deployed from the Lab each get a share page whose link carries a qhooks-hook-deployment manifest. It holds chain, addresses, configuration, build hash and the deployed code hashes. The page re-checks the manifest against the chain, and other tools can register it.

Public evidence checks

The terminal, hook inspector, wallet view and launch share page can request a dated RepoProof report for the selected public address. Reports retain individual findings and provider receipts; they do not certify source code or admit a hook to the launchpad.

GET /api/repoproof/check?kind=token&chainId=8453&address=0x… reads the existing cache only. It never starts a scan. The response identifies the exact subject and includes state, report, cached, stale, checkedAt, retryAt and reason. A cache miss is not_checked.

Within QHooks, an explicit Check action sends POST /api/repoproof/check with JSON {"kind":"token","chainId":"8453","address":"0x…"}. That action shares the selected public address and chain with RepoProof. POST requires the same origin and is not a cross-origin partner scan API; it grants no wallet or trading authority.

  • Subjects. EVM supports token, wallet, launch and contract on chain IDs 1, 8453, 42161, 56 and 4663. Solana supports token and wallet with chainId: "solana". Returned evidence depends on provider coverage.
  • Time and receipts. Reports are fresh for two minutes and can remain in cache for one hour. Reading or redisplaying a report does not renew its observation time. Receipts retain provider, status, capture time, byte count and response hash; raw transport and session credentials are omitted.
  • Shared capacity. New checks are limited to 20 globally and 5 per client per hour, with one in flight. Respect retryAt and HTTP Retry-After on 429; upstream backoff is shared. Partner capacity needs a separate integration agreement.
  • Unavailable evidence. Missing reads and partial coverage remain unknown. A historical simulation or a quiet report is not a promise that a later trade will succeed.

Use the Elysium JavaScript SDK and read-only integration example. Public SDK modules and GET responses support cross-origin reads without credentials.

import {createElysiumClient} from 'https://qhooks.com/sdk/elysium.mjs';
const qhooks = createElysiumClient();
const {venues} = await qhooks.venues();
const venue = venues.find(item => item.protocol === 'uniswap-v4');
if (venue) {
  const observed = await qhooks.pools(venue.id);
  console.log(observed.pools, observed.window, observed.coverage);
  const pool = observed.pools[0];
  if (pool) {
    const recent = await qhooks.swaps(venue.id, pool.poolId);
    console.log(recent.swaps, recent.window, recent.coverage);
  }
}

Pool scans cover the returned window, not all chain history. Check the source and observation time, retain the last readable result on refresh failures, and use exact pool, asset and transaction identities.

Limits and notes

  • Responses are cached for a few seconds at the edge. Please poll no faster than every 5 seconds per endpoint.
  • Launch market endpoints show launches listed on Markets; quotes are served only for their pools. Discover includes the broader sourced hook board.
  • There are no webhooks yet; poll /markets or use the Telegram bot for alerts.
  • Hook inspections (inspector) are read-only, and paid inspection is switched off.
  • Contracts are not independently audited. Nothing here is investment advice.
