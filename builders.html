What a module is

A contract a launch names as one of its payees. When anyone calls the launch's release(), the module receives its share in the token and the pair currency, by plain transfer. Everything else (who earns it, when, how) is up to your module.

One copy per launch, deployed by anyone through the deterministic deployer 0x4e59…956C with the marketplace salt keccak256("qhooks.module.v1") and

init = creationCode ++ abi.encode(token, quote, builder, uint16 builderBps)

so its address is known before the launch exists. Studio writes that address into the launch's split.

The template

QModuleBase counts new income as its balance minus what it already accounts for, takes your share off the top and hands the rest to your module. Your share is paid only to you, through claimBuilder(), which anyone can call.

contract MyModule is QModuleBase {
  constructor(address token, address quote,
              address builder, uint16 builderBps)
    QModuleBase(token, quote, builder, builderBps) {}

  function kind() external pure override
    returns (string memory) { return "my-module"; }

  // Every deposit you hold + everything booked and unpaid.
  function _reserved(uint256 i) internal view override
    returns (uint256) { ... }

  // Your share of new income, after the builder's cut.
  function _income(uint256 i, uint256 net) internal override { ... }
}

Call _intake(i) or _syncAll() at the start of every function that moves funds, before pulling deposits.

What the code guarantees

  • Your cap is 10%. builderBps above 1,000 does not deploy, and the registry refuses it.
  • Only the launch's share. A module receives exactly the share the creator set in the split; your cut comes out of that, never out of the creator's or anyone else's.
  • Fixed at deployment. Builder and share are constructor arguments, part of the module's address. Nobody can change them, you included.
  • No owner. Modules have no admin and no upgrade. The registry lists and pauses; it never touches funds.

What review looks for

The short version of the full checklist:

  • Creation code matches the source at your commit, byte for byte.
  • Every user deposit is in _reserved, so it is never counted as income.
  • Users can always get their deposits back; payouts never exceed what came in (fuzz test it).
  • Depositing around a payout cannot capture it.
  • Plain copy: what holders get, what they risk.

Tests

Submit Foundry tests: one per function, a fuzz test of the payout invariant, and one where a real launch pays your module. The marketplace suite has the helpers (deployVia, moduleInit, launchPaying).
